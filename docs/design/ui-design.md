> 最后更新：2026-06-24（v1.2 — 复查修订：修复色彩矛盾、补充图标规范、label、viewport、emoji 禁令）

## 1. 设计原则

### 品牌基调
- **镜子，不是导师**：UI 应该像一面干净的镜子——不抢眼、不装饰、不讨好
- **推进感**：每一次交互都应该让用户感觉到"我被推了一步"
- **透明**：诊断逻辑可见——用户看到的不只是结论，是判断过程
- **不评价**：界面不说"写得好"、"真棒"——不用绿色对勾、金色星星这类暗示"正确"的视觉元素
- **无装饰性图标**：不使用 emoji 作为 UI 图标；所有图标使用 SVG（Lucide / Heroicons），保持视觉克制

### 情绪板关键词
- 精准、干净、克制、没有废话
- 不冷淡——但绝不热络
- 像一个专业的朋友，不是一个热情的销售

## 3. 色彩系统

| 用途 | 颜色 | 说明 |
|------|------|------|
| 背景 | `#FAFAF9`（暖白石） | 不是纯白——微微偏暖，降低屏幕的冷感 |
| 前景/文字 | `#1A1A1A`（近黑） | 清晰但不刺眼 |
| 次要文字 | `#525252`（深灰） | 维度观察、辅助说明；对比度 6.4:1 通过 WCAG AA |
| 占位/禁用文字 | `#8A8A8A` | TextArea placeholder、按钮禁用态 |
| 强调 | `#0D0D0D`（纯黑边框） | 用于分隔线和关键标记 |
| 动作按钮 | `#1A1A1A` 底 + `#FFFFFF` 字 | 黑底白字，确定但不叫嚣 |
| 次要按钮 | 透明底 + `#1A1A1A` 边框 | 轮廓按钮 |
| 聚焦环 | `#1A1A1A`（2px 外框） | Focus ring，与品牌色系统一 |
| 无彩色反馈 | — | 不用红绿表示好坏 |

### 配色逻辑
- **不用绿色**：绿色暗示"正确/好"——工具不评价好坏
- **不用红色**：红色暗示"错误/差"——诊断不是纠错
- 用**黑、白、灰**——诊断是中性的反射
- 纯黑白灰的层次足够区分所有信息层级——不需要额外的 accent color

## 4. 字体与排版

### 字体家族

| 用途 | 字体 | 大小 |
|------|------|------|
| 标题 | system-ui sans-serif | 18px / 600 weight |
| 正文 | system-ui sans-serif | 15px / 400 weight（移动端 16px） |
| 用户输入文字 | serif（衬线体——写作场景暗示） | 15px |
| 诊断报告标题 | system-ui sans-serif | 16px / 600 weight |
| 维度观察 | system-ui sans-serif | 13px / 400 weight / 次要色 |
| 动作指令 | system-ui sans-serif | 15px / 500 weight |

### 排版

| 属性 | 值 | 说明 |
|------|-----|------|
| 正文 line-height | 1.6 | 诊断报告文字行距略大，降低阅读密度 |
| 输入区 line-height | 1.75 | 写作场景——宽松行距鼓励编辑 |
| 每行最大宽度 | `max-w-prose`（≈65ch） | 诊断报告区，避免过长行导致的阅读疲劳 |
| 段落间距 | `mb-4`（≈16px） | Section 之间用留白而非分割线 |
| 列表间距 | `space-y-2`（≈8px） | 三维度条目之间 |

### 字体备选（如需使用 Web Font）
- 正文字体备选：`Inter`（Google Fonts）——中性与 system-ui 感官一致
- 用户输入衬线体备选：`Source Serif 4` 或 `Noto Serif SC`（中文）
- 原则：优先 system font，Web font 仅在需要统一跨平台渲染时使用

## 5. 组件规范

### 通用交互规则
- **图标**：统一使用 Lucide 或 Heroicons SVG 图标（`24×24 viewBox`，`w-6 h-6`），禁止 emoji 做功能性图标
- **最小触摸目标**：所有可点击元素 ≥ 44×44px（WCAG 2.5.5）
- **cursor-pointer**：所有可点击/悬停元素添加 `cursor-pointer`
- **hover 反馈**：hover 时提供视觉反馈（颜色变化、边框加深），不使用 scale 变换（避免布局偏移）
- **过渡时间**：所有微交互使用 `transition-all duration-200`（150-300ms 范围）
- **动画属性**：仅对 `opacity` 和 `transform` 做动画——不对 `width`/`height` 做动画以保持 60fps
- **focus ring**：聚焦时显示 `outline-2 outline-offset-2 outline-neutral-900`
- **防重复提交**："开始诊断"按钮点击后即时禁用（`disabled` + `cursor-not-allowed`），不等待 API 响应

### 输入区
- TextArea 必须有 `<label>` 关联（`htmlFor` + `id`），不可仅依赖 placeholder 作为标签
- 文本框最小高度 200px，可自由拖拽扩展
- 占位文字："把你觉得不对劲的文字贴过来..."
- 占位文字颜色：`#8A8A8A`
- 右下角显示字数：`128 字`（次要色小字）
- 字数 ≤20 时，字数显示变灰，"开始诊断"按钮置灰
- 字数 >500 时，显示提示："文字较长，系统会挑出最需要诊断的段落"
- 输入框获得焦点时：边框从 `#0D0D0D` 变为 `#1A1A1A`，轻微加深

### 诊断按钮
- 文案："开始诊断"
- 最小尺寸：高 48px，宽 140px（满足 44px 触摸目标）
- 状态：
  - **正常**：`bg-[#1A1A1A] text-white`，`cursor-pointer`
  - **hover**：`bg-[#0D0D0D]`（微加深）
  - **加载中**：禁用 + 显示三点脉动动画 + `cursor-not-allowed`
  - **已禁用**（字数不足）：`opacity-40 cursor-not-allowed`
- 加载动画：三点依次淡入淡出，间隔 200ms；`prefers-reduced-motion` 时改为静态省略号
- 防抖：点击后立即 `disabled`，API 返回或超时后恢复

### 诊断报告区
- 每个 Section 之间有清晰的分隔（细线或 `mb-6` 留白）
- 报告区最小高度：300px（防止加载完成时布局跳动）
- "我注意到"段——左边框（`border-l-2 border-neutral-900 pl-4`），区分于其他段落
- "→ 动作指令"使用加粗样式（`font-medium`），这是用户最需要看到的东西
- 三个维度使用略小的字号和次要色——它们是辅助信息
- 内容区最大宽度：`max-w-prose`（≈65ch），避免行过长

### "换一个角度"按钮
- 仅在诊断结果展示后出现
- 文案："不对，换一个角度"
- 最小尺寸：高 44px
- 样式：次要按钮（透明底 + 边框）
- 点击后重新调用 API（携带 retryCount）
- 按钮旁显示当前角度序号（如"角度 1/2"），让用户知道追问是有限次的
- 第 3 次后文案变为"换一段文字试试"

### Footer
- 固定文案："这是镜子，不是答案。笔在你手里。"
- 字号 13px，次要色

## 6. 交互规范

### 状态流转
```
初始状态（输入区空白，报告区隐藏）
    ↓ 用户输入文字
就绪状态（按钮可点击）
    ↓ 点击"开始诊断" → 按钮即时禁用（防重复提交）
加载状态（按钮禁用 + 骨架屏，aria-busy="true"）
    ↓ API 返回（成功）
完成状态（渲染诊断报告，骨架屏淡出 200ms）
    ├→ 用户点击"换一个角度"
    │   ↓ 按钮即时禁用
    │   加载状态 → 完成状态（新诊断结果）
    ├→ 用户修改输入文字 → 再次点击"开始诊断"
    │   ↓
    │   加载状态 → 完成状态（含进步指认）
    └→ 用户清空输入 → 回到初始状态
    ↓ API 返回（失败）
错误状态（显示错误信息，role="alert"）
```

### 加载与骨架屏
- 骨架屏在报告区预占 300px 最小高度，防止内容跳动
- 骨架屏元素：三段灰色脉冲条（模拟"我注意到"、读者效果、动作指令的行长）
- 脉冲动画：`animate-pulse`，2s 周期
- `prefers-reduced-motion` 时：静态灰色条，无脉冲
- API 返回后骨架屏 `opacity` 淡出 200ms，报告内容淡入

### 错误状态
- API 超时（>30s）："等待超时——再试一次。"
- API 错误：显示具体错误信息
- 文字太短（≤20字）：按钮不可点击，字数提示加粗 + 底部出现提示线（不用红色——违反色彩系统原则）
- 错误信息使用 `role="alert"` 确保屏幕阅读器即时朗读

### 追问流程（"不对，换一个角度"）
- 第 1 次点击：换 Y，重新诊断（按钮旁显示"角度 1/2"）
- 第 2 次点击：换 X，走新路由（按钮旁显示"角度 2/2"）
- 第 3 次点击同一段文字：提示"把前后文也贴过来——或者换一段你觉得最'不对劲'的文字"
- 按钮在第三次后变为"换一段文字试试"

### 断点与响应式
- **viewport meta**：`<meta name="viewport" content="width=device-width, initial-scale=1">`（必须）
- **禁止水平滚动**：所有断点下内容必须适配视口宽度，不出现 `overflow-x`

| 断点 | 宽度 | 布局行为 |
|------|------|---------|
| 手机 | 375px – 767px | 上下排列，输入区和报告区全宽，字号 ≥ 16px |
| 平板 | 768px – 1023px | 上下排列，内容区 `max-w-2xl` 居中 |
| 桌面 | 1024px – 1439px | 左右分栏（输入左 40% + 报告右 60%） |
| 宽屏 | ≥ 1440px | 左右分栏 + 内容区 `max-w-7xl` 整体居中 |

### Z-Index 分层

| 层级 | z-index | 用途 |
|------|---------|------|
| 内容层 | `0` / `auto` | 正常文档流 |
| 悬浮元素 | `10` | 粘性按钮、浮动字数统计 |
| 遮罩层 | `20` | 骨架屏、加载遮罩 |
| 覆盖层 | `30` | Toast 通知、追问提示气泡 |
| 最高层 | `50` | 模态框（预留，v1 不使用） |

规则：各层之间保持 ≥10 的间隔，避免意外覆盖。

## 7. 无障碍

### 基础要求
- 全键盘可操作（Tab 导航、Enter 提交）
- 色盲友好（不依赖红绿区分信息）
- 屏幕阅读器：诊断报告使用语义化 HTML 结构（`<article>`、`<section>`、`<h2>` 等）

### Focus States（聚焦状态）
- 所有可交互元素必须有可见的 focus ring
- 样式：`outline-2 outline-offset-2 outline-neutral-900`（与品牌色系一致）
- 不使用 `outline-none` 除非有替代的聚焦指示
- Tab 键导航顺序 = 视觉顺序（输入区 → 诊断按钮 → 报告区 → 换角度按钮）

### 对比度
| 元素 | 前景 | 背景 | 对比度 | 标准 |
|------|------|------|--------|------|
| 正文 | `#1A1A1A` | `#FAFAF9` | 18.0:1 | AAA ✅ |
| 次要文字 | `#525252` | `#FAFAF9` | 6.4:1 | AA ✅ |
| 占位文字 | `#8A8A8A` | `#FAFAF9` | 3.8:1 | — (仅 placeholder) |
| 按钮白字 | `#FFFFFF` | `#1A1A1A` | 18.0:1 | AAA ✅ |

### ARIA 标注
- 图标按钮（如换角度按钮旁的小图标）必须有 `aria-label`
- 加载状态：`aria-busy="true"` + `aria-live="polite"` 播报状态变化
- 错误信息：`role="alert"` 确保屏幕阅读器即时读出

### prefers-reduced-motion
- 加载动画在 `prefers-reduced-motion: reduce` 时禁用动画，改为静态省略号
- 所有 transition/animation 放在 `@media (prefers-reduced-motion: no-preference)` 内
