## 文档概述

本文档记录了写作诊断工具从 v3.1（单状态诊断 Prompt）到"全状态 X→Y→Z 写作推动系统"的完整重新设计。设计过程经过：

- 一轮用户意图深访（从"底层动机"到"双入口需求"）
- 五条理论线锚定（Polanyi、Merleau-Ponty、SDT/Lewin、Vygotsky/Bruner、Frankl/Rollo May）
- 三轮 DeepSeek 外部审查（边缘漏洞 + 结构补丁）
- 四章递进设计（架构 → 引擎 → Prompt → 产品体验）

# 一、产品定位

## 一句话定位

> **用文字看清自己。**

六个字，肯定式，无术语。同时覆盖双入口——有文字的人从这里进去，没文字的人也从这个方向被牵引。

## 核心骨架

- **X→Y→Z 框架**：项目唯一不可推导的起点。X（读者感受到什么效果）→ Y（执行层缺了什么）→ Z（现在要做的动作）
- **灵魂**：推进不是陪伴。镜子不陪、不替、不评价——只反射，让用户看见自己文字里本已存在但尚未意识到的东西。

## 目标用户

"中间地带"的人——与现实若即若离，有东西想表达，但表达和感知之间存在裂缝。裂缝来源：社会阅历与认知水平的错位（阅历缺失+认知早熟，或阅历过剩+认知滞后）。

## 与 v3.1 的核心区别

| | v3.1（当前） | 新版（本设计） |
|---|---|---|
| 入口 | 单入口——需要用户先拿出文字 | 双入口——有文字/没文字都能进来 |
| 工作场景 | 仅在"写作中"状态 | 覆盖空虚→模糊念头→写作中→卡住了→写完了 |
| 产品形态 | 单场景诊断工具 | 写作者全阶段推动系统 |
| System Prompt 结构 | 三层平铺（~5000 tokens 始终加载） | 四层条件执行（~900 tokens 始终加载，最坏 ~5400） |

# 二、项目铁律

## 产品层铁律（继承 v3.1 铁律 1-10，不改动）

1. 推进是第一目的
2. 每句话说完，他必须能接
3. 不评价好坏
4. 不替他写
5. 不给台阶
6. 判断要确定
7. 不问空问题
8. 不用术语
9. 只诊断当前文字
10. 不命名用户

## 项目层铁律（新增）

> **每加一个机制，必须回答：这个机制让用户多看见了自己的什么？**
> **如果答案是"让镜子更准"——不加。**
> **如果答案是"让用户多看见了X"——加，并在设计文档中标明它照亮了用户的哪一块。**

哲学基础：镜子不是目的——用户看见自己才是目的。镜子变锋利是手段，但如果锋利到用户只看见镜子而看不见自己——镜子就背叛了它的目的。

# 三、理论底座

设计团队（人类 + AI）从现象学、动机心理学、教育心理学、存在心理学和认知科学五个领域锚定了 X→Y→Z 的理论基础：

| 理论来源 | 核心概念 | 解释了项目的哪个问题 |
|----------|---------|-------------------|
| Michael Polanyi | 隐性知识——人知道的永远比能说的多 | 裂缝不是能力问题，是隐性知识→显性表达的自然损耗 |
| Merleau-Ponty | 身体-主体——表达是身体在说话，不是大脑在翻译 | 裂缝是身体方向与符号出口之间的裂隙 |
| Deci & Ryan (SDT) | 内在动机三需求（自主/胜任/关联）+ 外在触发可被内化整合 | 双动力来源不是对立的——外在触发通过释放内在动机生效 |
| Kurt Lewin | 场论——行为=人×环境。空虚是场域张力均等，触发打破均衡 | 外在微小念头之所以有效——它改变了心理场域的区域张力 |
| Vygotsky | 最近发展区（ZPD）——独立上限与引导上限之间的区域 | 双入口的用户在 ZPD 的不同位置，需要同一套脚手架的不同搭法 |
| Jerome Bruner | 脚手架理论——引导是搭临时结构，随能力增长撤除 | v3.1 消隐已在做——但只在诊断端，入口端还没有 |
| Viktor Frankl | 存在真空——意义意志受阻，找不到做任何事的理由 | 空虚状态 ≠ 能力缺失。工具的任务是帮用户"面对空白而不逃跑" |
| Rollo May | 创造行为本身就是对空虚的回应——在不知道有什么时仍选择面对 | 引导的本质：不是给答案填补空虚，是帮用户面对空白 |
| Donald Schön | 行动中反思——实践者通过看自己做了什么来校正下一步 | 镜子 = 行动中反思的外部化 |
| John Flavell | 元认知三成分（知识/体验/策略） | X→Y→Z = 元认知策略的结构化外部实现 |

# 四、全状态 X→Y→Z 引擎

## 4.1 五状态判定表

| 状态 | 判断信号 | X（镜子看到的） | Y（卡在哪） | Z（最小动作） | 流转规则 |
|------|---------|--------------|-----------|------------|---------|
| **空虚** | 输入 < 20 字，无具体名词/动词 | 感知不在身体里 | 用户和自己身体感受之间断了 | "闭上眼睛想30秒——你身体哪个地方最紧？" | 用户回应身体感受 → 模糊念头；用户直接写了一段文字 → 写作中 |
| **模糊念头** | 有方向词（"关于""想写"），但无具体场景/人物/动作 | 有方向没有落点 | 方向和具体执行之间缺桥 | "不要说'什么'——说一个具体的物件。" | 用户给出具体物件 → 写作中（弱起）；用户说"还是没想法" → 空虚 |
| **写作中** | 输入 > 50 字，有具体叙事（人物/动作/对话/场景至少两项） | 继承 v3.1 X 七类效果 | 继承 v3.1 四类 Y | 继承 v3.1 Z 动作指令 | 用户说"不对"/重复修改 → 卡住了；用户说"你觉得怎么样" → 写完了 |
| **卡住了** | 两轮文本长度变化 < 20% 且重复 > 70%；或用户说"不对"/"还是不对" | 首轮：文字中有一处在反复打磨但没磨亮；次轮起：上一轮 Z 没推到真正障碍 | 用户和真问题之间隔了看不见的东西 | 交错操作：朗读，找到不舒服的句子 | 用户找到句子并改写 → 写作中；用户说"读不出来" → 写作中（不强制交错） |
| **写完了** | 提交文字 > 50 字 + 用户明确表达不确定（"你觉得怎么样"/"会不会太…"） | 效果链完整但用户看不见 | 元认知判断和实际效果有偏差 | "从头读一遍——哪个句子让你想停下来再看一眼？" | 用户提交新文字 → 写作中；用户说"就这样吧" → 结束 |

### "弱起"定义

"弱起"状态是模糊念头→写作中的过渡带：用户已有一个具体物件，但尚未形成叙事链条。此时的 Z 动作是围绕物件问最小问题——"如果这物件有声音，它会说什么？"或"谁曾经拥有它？"——把物件推向人物和历史，为叙事铺路。

## 4.2 状态流转规则表

| 当前状态 | 用户响应信号 | 下一状态 |
|----------|-------------|----------|
| 任意 | 用户否定状态判断并给出替代描述 | 按用户描述重入 |
| 空虚 | 用户说出身体感受 | 模糊念头 |
| 空虚 | 用户直接写了一段文字（> 50 字） | 写作中 |
| 模糊念头 | 用户给出具体物件并开始描述 | 写作中（弱起） |
| 模糊念头 | 用户说"还是没想法"，无新内容 | 空虚 |
| 写作中 | 用户说"不对"/"还是不对"，或连续提交差异 < 20% | 卡住了 |
| 写作中 | 用户说"你觉得怎么样"/"会不会太…" | 写完了 |
| 写作中 | 用户提交新的、有实质进展的文字 | 写作中 |
| 卡住了 | 用户找到句子并尝试改写 | 写作中 |
| 卡住了 | 用户说"读不出来"，无新内容 | 写作中 |
| 写完了 | 用户提交修改后的文字 | 写作中 |
| 写完了 | 用户说"就这样吧"或不再提交 | 结束 |

## 4.3 全局规则

**规则一：状态确认**

每一轮诊断第一句——镜子公开状态判断："我注意到你现在是[状态]——对吗？"
- 用户确认 → 继续
- 用户纠正 → 用纠正后的状态重入

**规则二：确认频率豁免**

- 用户连续两轮处于同一状态且未否定判断 → 第三轮起可跳过确认
- 例外：用户提交内容的字数或结构发生显著变化时，豁免权暂停一轮——镜子重新确认

**规则三：结束非终态**

用户再次提交任何文字时，重新执行状态识别流程。本轮对话内的状态流转历史被重置。

## 4.4 与 v3.1 的衔接

- **写作中**状态完整继承 v3.1 三层诊断：悬置操作 → X 判定（七类效果）→ X→Y 路由 → Y 定位（四类缺陷）→ Z 推动 → 三维度观察 → 指月收束
- **写完了**状态在 v3.1 出口三基础上增加元认知偏差校准——用户表达不确定时，不只反射完整感，还帮用户验证他的不确定
- **出口判定**（结构缺失/执行偏倚/干净）仅在"写作中"和"写完了"状态下触发
- 入口信号区分：用户只提交文字不说话 → 默认走 v3.1 标准诊断；用户提交文字 + 表达不确定 → 走"写完了"状态

# 五、System Prompt 架构

采用**分层单 Prompt + 条件执行**模式。

## 架构总览

```
┌──────────────────────────────────────────────────────┐
│ Layer 0：核心身份（~200 tokens）                      │
│ · "用文字看清自己"                                   │
│ · 镜子哲学（庄子三句 + 操作含义）                     │
│ · 铁律 1-10 + 项目铁律                                │
│ · 此层始终加载                                       │
├──────────────────────────────────────────────────────┤
│ Layer 1：状态识别与确认（~300 tokens）                │
│ · 五状态判断信号（词性/字数/关键词/内容特征）          │
│ · 状态确认规则（公开判断+等确认）                      │
│ · 确认频率豁免 + 例外                                 │
│ · 此层始终加载                                       │
├──────────────────────────────────────────────────────┤
│ Layer 2：状态→X→Y→Z 映射表 + 流转规则（~400 tokens）  │
│ · 五状态 X→Y→Z 速查表（一行一个状态）                 │
│ · 流转规则表（触发条件→目标状态）                      │
│ · "弱起"定义 + 弱起 Z 动作                            │
│ · 结束非终态规则                                      │
│ · 此层始终加载                                       │
├──────────────────────────────────────────────────────┤
│ Layer 3：v3.1 完整诊断（~3000 tokens）                │
│ · 执行条件：仅当状态=写作中 或 写完了时加载            │
│ · 悬置操作 → X 判定 → X→Y 路由 → Y 定位 → Z 推动     │
│ · 三维度观察 + 指月收束 + 出口一/二/三                 │
│ · 完全复用 v3.1 原文，不做删减                         │
├──────────────────────────────────────────────────────┤
│ Layer 4：故障处理（~1500 tokens）                      │
│ · 执行条件：仅当用户否定诊断时加载                     │
│ · 偏倚→结构回检（强/弱/累积触发）                      │
│ · 回退系统（出口一/二/三 × 三级）                       │
│ · 侧面描述 + 交错操作 + 镜子消隐                       │
│ · 完全复用 v3.1 第三层原文                             │
└──────────────────────────────────────────────────────┘
```

## 加载统计

| 场景 | 激活层 | Token |
|------|-------|-------|
| 始终加载 | Layer 0 + 1 + 2 | ~900 |
| 写作中（用户接受诊断） | + Layer 3 | ~3900 |
| 写作中 + 用户否定 | + Layer 3 + 4 | ~5400 |
| 空虚/模糊念头/卡住状态 | Layer 0 + 1 + 2 only | ~900 |

对比 v3.1：原版始终加载 ~5000 tokens。新版始终加载 ~900 tokens（减少 82%），最坏情况 ~5400（略多于原版但覆盖了五状态）。

# 六、双平台产品体验

## 6.1 Web App（主产品 · 深度体验 · 变现）

### 输入体验

一个输入框，不区分状态。placeholder："在这里写任何东西——一段小说、一句'我不知道写什么'、一个念头、一段不确定的文字。"

### 诊断展示

提交后展示：状态确认行 → 诊断正文 → [继续写] / [不满意，换个角度] → 历史记录。

### 付费模型

| 层级 | 额度 | 说明 |
|------|------|------|
| 免费 | 每日 3 次 | 新用户默认 |
| 按量 | 10 次 / 50 次 | 价格待定 |

### 计费规则

```
用户提交 → 镜子输出诊断 → 计数 -1（仅此一次）
    │
    ├── 继续写 → 新提交 → 计数 -1
    │
    └── 不满意→换个角度 → 重新诊断（不扣费）
                              │
                         直到用户满意→继续写
```

- 状态确认轮不计费（首次确认免费）
- 用户纠正状态判断后，纠正后的诊断轮计费
- 回退不计费——同一段文字的回退链不重复扣
- 历史记录回看不计费——展示已存储的完整诊断报告，不重新调用 LLM

## 6.2 微信生态（低门槛入口 · 引流）

### 公众号：接住

- 用户发任何文字 → 返回状态确认 + 轻量诊断（1-2 句反射）+ Z 动作
- 每条回复末尾："镜子在小程序里能看到更多——[小程序链接]"
- 不做付费，纯引流入口
- 注意：微信客服消息上限 48h/20条，前期不实现异步队列，文档留接口

### 小程序：试用

- 同 Web App 一个输入框 + 完整诊断展示
- 第 1 次诊断时告知边界："小程序端 3 次免费，完整档案和连续对话在 Web App"
- 3 次免费诊断后 → 引导至 Web App 付费页面（浏览器打开）
- 小程序端不实现支付闭环
- 诊断记录通过手机号绑定可迁移至 Web App

### 三者关系

```
公众号（接住）
    ↓ 返回轻量诊断 + 小程序链接
    ↓ 点击 → 小程序

小程序（试用）
    ↓ 首次告知边界
    ↓ 用完 3 次 → 跳转浏览器打开 Web App 付费

Web App（深度）
    ↓ 付费用户
    ↓ 完整诊断 + 历史记录 + 写作档案 + 多轮对话
```

## 6.3 数据与身份衔接

### 用户身份

- 微信端：公众号用 OpenID 做临时标识（不持久化）；小程序用 OpenID 做用户标识
- **注意**：微信 OpenID 分应用隔离——公众号和小程序下是不同 OpenID
- Web App：邮箱注册或匿名
- **桥接**：手机号作为唯一用户主键。OpenID 降级为"登录凭证"

### 同步方向

单向：微信端 → Web App。Web App 是最终数据存储地。

### 数据模型

```
用户表
  - id (主键)
  - phone (唯一，绑定时填写)
  - wechat_openids: [] (公众号 + 小程序 OpenID)
  - web_anonymous_id (可选)
  - created_at

诊断记录表
  - id (主键)
  - user_id (外键 → 用户表)
  - state: "空虚" | "模糊念头" | "写作中" | "卡住了" | "写完了"
  - user_text_preview: string (50 字)
  - diagnosis_summary: string (一句话摘要)
  - full_diagnosis: string (完整诊断报告全文)
  - created_at

轮次表（计费）
  - id (主键)
  - user_id (外键 → 用户表)
  - is_free_tier: boolean
  - consumed_at: timestamp
```

### 数据生命周期

- **原文**：仅存在于运行时（Deno 内存），诊断完成且用户进入下一轮后丢弃。不落数据库。
- **50 字预览**：存储到数据库（用于历史记录列表展示）
- **诊断摘要**：存储到数据库
- **完整诊断报告**：存储到数据库（用于回看。诊断报告是对原文的反射，不是原文本身——不违反"不存原文"承诺）

### 隐私声明

输入框下方一行："你的文字只在这一轮诊断中使用。诊断结束后不保存完整原文。"

# 七、设计演进录

本节记录设计过程中被识别并修复的漏洞，防止后续实现时重复踩坑：

| 漏洞 | 发现阶段 | 修复方案 |
|------|---------|---------|
| X→Y→Z 无法处理无文字状态 | 第 1 章自审 | X→Y→Z 扩展至全状态——用户对工具说的每一句话都是文本 |
| LLM 隐式状态分类不稳定 | DeepSeek 审查 R1 | 每轮第一句公开状态判断，等用户确认 |
| "卡住了"判定依赖次数而非语义 | DeepSeek 审查 R1 | 改为文本变化幅度（长度变化 < 20% + 重复 > 70%） |
| "写完了"与 v3.1 出口三边界模糊 | DeepSeek 审查 R1 | 入口信号区分——用户是否主动表达不确定 |
| 空虚状态 Z 后循环误判 | DeepSeek 审查 R2 | 流转规则——用户回应身体感受后自动进模糊念头 |
| 卡住状态首次进入无"上一轮 Z" | DeepSeek 审查 R2 | 备选 X——"文字中有一处在反复打磨但没磨亮" |
| 写完了与模糊念头边界 | DeepSeek 审查 R2 | 加字数条件——提交文字 > 50 字 |
| 状态确认无限循环免费旁路 | DeepSeek 审查 R3 | 仅首次确认免费，纠正后诊断计费 |
| 历史记录隐私与上下文矛盾 | DeepSeek 审查 R3 | 存 50 字预览+诊断摘要+完整报告，不存完整原文 |
