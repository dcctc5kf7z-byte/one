# Skill 迁移规划 — Hermes 资产提取到 Skill

> 日期：2026-06-29
> 背景：Skill 优先决策后，从 Hermes（Web App Edge Function）提取可复用资产到 Claude Code Skill
> 原则：只迁移对 Skill 诊断质量有直接提升的资产，UI 层资产（ColorBar/GutterBlock/HistoryPanel）不迁移

---

## 资产盘点

### Hermes 拥有的资产

| 资产 | Hermes 位置 | 类型 | Skill 已有？ |
|------|-----------|------|------------|
| 6 色信号系统 | `hermes-types.ts` + Hermes prompt | 诊断词汇 + UI 渲染 | **部分** — 透镜动作句中已引用颜色名，但无独立定义文档 |
| 6 维焦距分析 | `focal-engine-spec.md` + Hermes prompt | 分析原语 | **部分** — G-1 规格已写完（958行），7 透镜各有焦距优先级，但无跨体裁统一参考 |
| X→Y→Z 模型 | Hermes prompt + SKILL.md | 诊断框架 | **已有** — SKILL.md 已包含完整 X→Y→Z 模型 |
| 写作指纹 | `FingerprintManager.ts` | 跨会话模式追踪 | **无** — Skill 无跨会话状态 |
| 植物状态机 | `hermes-types.ts` (PlantState) | 用户成长可视化 | **无** — 纯 UI 概念 |
| G-5 动作句模板 | `action-sentence-templates.md` | 输出格式化 | **已有** — 7 透镜均已集成 |

### 结论：真正需要迁移的只有 2.5 个资产

1. **6 色信号 → 独立参考文档**（P0，~30 分钟）
2. **G-1 焦距引擎 → 透镜统一引用**（P1，~1 小时）
3. **写作指纹 → Skill 会话协议**（P2，需设计，~2 小时）

---

## M-1：6 色信号参考文档（P0）

### 现状

透镜动作句中已使用颜色名（胭脂红/钢蓝/堇紫等），但没有一个独立文档定义这套系统。当前 Skill 加载链路中，如果 AI 模型不熟悉这套颜色语义，颜色名就是噪音。

### 方案

创建 `.claude/skills/writer/reference/hermes-color-signals.md`，内容：

```
# Hermes 6 色信号 — 诊断颜色参考

> 6 种颜色 = 6 种信号类型。每种颜色对应一种文本现象，有明确的触发条件和典型动作句。

| 颜色 | 中文名 | 信号 | 触发条件 | 动作句方向 |
|------|--------|------|---------|----------|
| crimson | 胭脂红 | 卡点 | 因果断裂、逻辑跳跃、阅读阻滞 | "这里停下来——" |
| amber | 琥珀黄 | 模式 | 句法重复≥2次、同一意象反复、节奏惯性 | "注意——一个模式在重复" |
| steel_blue | 钢蓝 | 推进 | 已写出但未展开的方向、有种子没发芽 | "这里有方向——" |
| violet | 堇紫 | 暗层 | 文字暗示但未直接说出、情绪/动机在字面下 | "想一想——文本下面还有一层" |
| slate_gray | 鼠灰 | 数据 | 句长异常、词频突出、可量化特征 | "数据——" |
| pine_green | 松绿 | 惯性 | 跨文本模式（≥3次出现）、与写作指纹匹配 | "你的惯性——" |

## 紧迫度排序

crimson → amber → steel_blue → violet → slate_gray → pine_green

## 使用规则

1. 诊断输出中不显示颜色名给用户——颜色是内部信号分类
2. 动作句中可使用颜色手势（G-5 §3）但不过度标注
3. 同一句子可触发多种颜色——取紧迫度最高者为主导
```

### 加载链路

在 SKILL.md 的加载规则中，将 `hermes-color-signals.md` 加入第三层（可选加载）：

```
第三层（透镜判定需要时加载·可选）:
  - reference/hermes-color-signals.md  — 6 色信号定义（跨体裁诊断词汇，按需加载）
```

### 透镜变更

各透镜文件在"焦距优先级与动作句方向库"节中，添加一行引用：

```
> 颜色信号定义见 [Hermes 6 色信号](../reference/hermes-color-signals.md)。
```

### 影响范围

- 新增 1 个文件：`reference/hermes-color-signals.md`
- 修改 1 个文件：`SKILL.md`（加载规则 +1 行）
- 修改 7 个文件：各透镜文件（+1 行引用）
- Token 增量：~300t（仅当加载颜色参考时）

## M-2：G-1 焦距引擎 → 透镜统一引用（P1）

### 现状

- `docs/tech/focal-engine-spec.md` 已写完（958 行），定义 6+1 维焦距分析的完整协议
- 7 透镜各有"焦距优先级"（如叙事：情感★★★/结构★★★/语言★★/...）
- 但：透镜与 G-1 规格之间没有**明确引用链**——透镜的焦距优先级是独立定义的，没有告知模型"为什么这个体裁优先这些焦距"

### 方案

在各透镜文件的"焦距优先级与动作句方向库"节中，添加 G-1 引用和焦距选择理由：

```markdown
## 焦距优先级与动作句方向库

> 焦距定义见 [G-1 六维焦距分析引擎](../../../docs/tech/focal-engine-spec.md)。
> 动作句 = 颜色手势（[G-5 §3]）+ 焦距证据（[G-5 §4]）+ 体裁方向（本节）。

**焦距优先级**：情感 ★★★ / 结构 ★★★ / 语言 ★★ / 语义 ★★ / 语用 ★★ / 批判 ★

**为什么这个优先级？**
- 叙事文本的核心驱力是人物内心变化（情感★★★）和因果链（结构★★★）
- 语言层修辞在叙事中是载体而非核心——降低优先级
- 批判层隐含假设在叙事中不常出现——仅作辅助
```

### Token 成本

每个透镜增加 ~80-120t（焦距选择理由）。7 透镜 = ~700t。仅在加载对应透镜时消耗。

### 影响范围

- 修改 7 个文件：各透镜文件（焦距优先级节 + 选择理由）
- 无需修改 SKILL.md

## M-3：写作指纹 → Skill 会话协议（P2）

### 现状

Web App 中，`FingerprintManager.ts` 使用 localStorage 追踪用户写作模式：
- 每次诊断后合并 pattern
- 同一 pattern 出现 ≥3 次 → 点亮 pine_green（松绿）
- 支持导出/导入 JSON

Claude Code Skill 无法使用 localStorage，但可以：
1. 读取 `profile/` 目录下的指纹文件
2. 每次诊断后写入/更新指纹文件

### 方案

#### 3.1 指纹存储格式

`.claude/skills/writer/profile/fingerprint.md`：

```markdown
---
name: writing-fingerprint
description: 用户写作模式追踪 — 跨会话写作指纹
updated: 2026-06-29T10:00:00Z
texts_analyzed: 12
---

## 活跃模式（≥3次，松绿）

| 模式类型 | 触发描述 | 频率 | 首次出现 | 最近出现 |
|---------|---------|------|---------|---------|
| 句法 | 连续短句（≤8字）后无长句换气 | 5 | 2026-06-15 | 2026-06-29 |
| 意象 | 水/液体意象反复出现 | 4 | 2026-06-20 | 2026-06-28 |

## 潜伏模式（<3次）

| 模式类型 | 触发描述 | 频率 | 首次出现 | 最近出现 |
|---------|---------|------|---------|---------|
| 逻辑 | 因果链中省略中间步骤 | 2 | 2026-06-25 | 2026-06-29 |
| 情感 | 高潮处突然降调 | 1 | 2026-06-29 | 2026-06-29 |

## 维度画像

- 句长倾向：短句偏好（均值 12.3 字/句）
- 修辞倾向：隐喻密度高（3.2 隐喻/千字）
- 情感调性：冷调为主（正面情感词占比 18%）
```

#### 3.2 SKILL.md 指纹协议

在 SKILL.md 中添加指纹协议节：

```markdown
## 写作指纹（可选功能）

当 `profile/fingerprint.md` 存在时：
1. 诊断前读取指纹，了解用户的跨文本模式
2. 诊断中若发现与已有模式匹配的信号 → 可引用松绿（惯性）信号
3. 诊断后更新指纹（SKILL 提示用户是否需要更新，不自动写入）

指纹更新阈值：
- 同一模式出现 ≥3 次 → 标记为"活跃模式"，诊断中可引用
- <3 次 → 标记为"潜伏模式"，诊断中不引用但记录
```

#### 3.3 加载链路

在 SKILL.md 加载规则中添加：

```
第零层（指纹预载·可选）: profile/fingerprint.md — 用户写作模式追踪（存在时预载，不存在时跳过）
```

### Token 成本

指纹文件预估 ~500-800t（含 5-10 个模式）。仅在 fingerprint.md 存在时消耗。

### 设计考量

- **不自动写入**：Skill 不应在用户不知情的情况下修改文件。诊断后提示用户"检测到 N 个可记录的模式，是否需要更新写作指纹？"
- **指纹与诊断分离**：指纹是辅助信息，不影响核心诊断流程。松绿信号仅在模式匹配时作为补充观察给出
- **渐进实现**：P2-1 先实现读取协议（让 Skill 能利用已有指纹），P2-2 再实现写入协议

## 实施优先级

| 编号 | 资产 | 优先级 | 预估时间 | Token 成本 | 依赖 |
|------|------|--------|---------|-----------|------|
| M-1 | 6 色信号参考文档 | **P0** | ~30min | +300t（可选加载） | 无 |
| M-2 | G-1 焦距统一引用 | **P1** | ~60min | +700t（按透镜加载） | M-1 |
| M-3.1 | 写作指纹读取协议 | **P2** | ~90min | +500-800t（可选加载） | 无 |
| M-3.2 | 写作指纹写入协议 | **P3** | ~90min | 0t（SKILL.md 增加协议节） | M-3.1 |

### 不做的事

- ❌ 不迁移植物状态机（sprout/growing/blooming/fruiting）— 纯 UI 概念，Skill 无需
- ❌ 不迁移 SentenseAnalysis 逐句分析 — Skill 做整体诊断，不做逐句标注
- ❌ 不迁移 GutterBlock 色块渲染 — UI 组件，Skill 不渲染
- ❌ 不迁移 ColorBar/SignalBar/ModeSlider — UI 组件
- ❌ 不迁移 HistoryPanel 会话历史 — Web App 功能，Skill 用 Claude Code 原生历史
