## 一、核心资产审计

在讨论变现之前，先明确你拥有什么——以及每项资产的市场稀缺度。

### 1.1 方法论 IP（高稀缺，高壁垒）

| 资产 | 一句话定义 | 市场稀缺度 | 竞品对比 |
|------|----------|----------|---------|
| **X→Y→Z 诊断模型** | 从读者效果反向定位执行缺陷 → 给出推进动作 | ★★★★★ | 市面上无同类——写作书给"建议"，不给诊断链 |
| **铁三角监控体系** | 因果功能 + 人物真实 + 读者张力——三角中任何一角松了场景就塌 | ★★★★☆ | McKee 讲结构但不讲三角联动；Truby 讲人物但不讲实时监控 |
| **五侧面路由系统** | 根据输入文本特征自动切换 AI 角色（破冰/同路/架构/引爆/追问） | ★★★★☆ | 所有写作 AI 都是"一个调子"——无人做状态感知和角色切换 |
| **推阻计数器 + 制高点** | 实时感知用户阻力，累积到阈值时切换至"捅破"模式 | ★★★★★ | 无竞品——这是交互设计，不是写作理论 |
| **回滚协议** | 承认误判 → 重新诊断 → 重新推进的三步机制 | ★★★☆☆ | 客服领域有，写作领域没有 |

### 1.2 结构化知识（高可迁移性）

v4 降维淬炼的核心成果：**21 个文件，1,001 行，其中 68% 是表格式内容**。

这意味着：
- 判定标准表 → 天然适合编程化为诊断 API
- 动作路由表 → 天然适合转化为交互式工作流
- 速查表 → 天然适合转化为教学材料（worksheet、卡片、检查清单）

### 1.3 品牌锚点（高辨识度）

| 锚点 | 类型 | 力度 |
|------|------|------|
| **"推进，不是陪伴"** | 核心主张 | ★★★★★——一句话区分整个 AI 写作赛道 |
| **"硬逻辑"** | 操作原则 | ★★★★☆——给"推进"提供了可操作的定义 |
| **"不问空问题"** | 行为准则 | ★★★★☆——所有写作者都经历过被问蠢问题 |
| **铁律体系（0-8）** | 信任建立 | ★★★☆☆——像"Asimov 三定律"一样的仪式感 |

### 1.4 用户特定资产（不可迁移，但可示范）

- 三声部写作画像（思辨体/叙事体/散文诗体）
- DNA 指纹弹药库（物象系统：空椅/铁皮/刀刃/杯沿/未锁的门）
- 私人概念体系（悬置/异化/how for/混沌）
- 中西思想工具混用的知识结构

> 这些不可变现，但它们是**案例故事**的绝佳素材——用你自己的写作过程来展示方法论的有效性。

### 1.5 资产价值总结

```
可迁移 IP 层（方法论 + 结构化知识）
    ↓ 转化为
内容产品（文章/课程/工作坊）
    ↓ 同时转化为
技术产品（诊断 API/插件/工具）
    ↓ 品牌承载
"推进，不是陪伴"
```

## 二、三层价值主张

同一个方法论，面向不同人群时，说不同的话。

| 层级 | 目标用户 | 痛点 | 价值主张 | 产品形态 |
|------|---------|------|---------|---------|
| **L1 写作者** | 卡住的中级写作者 | "我知道哪里不对劲，但不知道该怎么办" | **从模糊的'不对'到精确的'这里'——X→Y→Z 诊断链** | 免费内容 + 低价工具 |
| **L2 严肃写作者** | 正在完成长篇作品的写作者 | "我需要一个不会说'慢慢来'的人" | **推进，不是陪伴——一个真正推你往前走一步的写作教练** | 陪跑计划 + 诊断工具 |
| **L3 AI 开发者** | 做 AI 写作工具的产品经理/开发者 | "我们的 AI 只会说'写得好'和'或许你可以'" | **把写作诊断变成可编程的路由表——铁三角 + 五侧面 + 推阻计数器** | API + SDK + 白标方案 |

**核心洞察**：L1 做流量，L2 做利润，L3 做壁垒。

## 三、三阶段变现路线图

### 阶段一（0-6月）：建立认知 + 验证需求

**目标**：让 100 个写作者知道这套方法论存在，其中 10 个愿意为它付费。

#### 产品：免费内容 + 最小诊断工具

| 交付物 | 形态 | 工作量 | 目的 |
|--------|------|--------|------|
| **X 效果诊断表（公开版）** | 一篇文章 / 长图 | 2天 | 建立"这个方法论有东西"的第一印象 |
| **"你的写作卡在哪里？"自诊问卷** | Notion 表单 / Google Form | 1天 | 收集用户数据 + 邮件地址 |
| **铁三角自检卡片** | PDF 下载品（需要邮件） | 1天 | 建立邮件列表 |
| **最小可用诊断工具** | Claude API + 网页（文本→X→Y→Z 诊断） | 1周 | 验证"人们愿意让 AI 诊断自己的写作吗" |

#### 平台策略（详见第五部分）

| 平台 | 内容类型 | 频率 | 目的 |
|------|---------|------|------|
| **知乎** | 方法论长文（"你的写作有六种死法——X 效果判定表"） | 每周1篇 | 搜索流量 + 专业认知 |
| **小红书** | 诊断卡片图 + 短文案 | 每周2-3条 | 年轻写作者触达 |
| **豆瓣写作小组** | 免费诊断帖（"贴一段，我告诉你 X 效果是什么"） | 每天回复 | 直接获客 |
| **即刻 / Twitter** | 铁律金句 + 诊断链截屏 | 每天1条 | 建立"推进者"人设 |

#### 关键验证指标

- [ ] 方法论文章 ≥ 1,000 阅读
- [ ] 自诊问卷 ≥ 50 份回复
- [ ] 邮件列表 ≥ 30 人
- [ ] 诊断工具 ≥ 10 个回头用户
- [ ] 有 ≥ 3 个人主动问"你能帮我看看我的稿子吗"

#### 阶段一不做什么

- ❌ 不建网站（用现成工具）
- ❌ 不收高价（先验证人们愿意为诊断付费）
- ❌ 不开发复杂产品（一个 API call 能做的事不做前端）

### 阶段二（6-18月）：产品化 + 建立收入流

**目标**：月收入 ¥5,000-15,000，稳定付费用户 20-50 人。

#### 产品矩阵

**A. 写作诊断工具（SaaS，月付 ¥29-99）**

```
用户粘贴文本 → 
  X 效果判定（空洞/模糊/太快/停滞/断裂/外部过剩 六选一）
  → Y 缺陷定位（因果链/锚点/价值转换/人物/外部过剩 五选一）
  → Z 推进建议（具体问题 + 方向）
  → 铁三角健康度扫描（三角各自 ✓/✗）
  → 场景审计报告
```

- 免费版：每次 500 字，基础 X→Y→Z
- 付费版：无字数限制，铁三角 + CF 深层诊断 + 历史诊断记录

**B. "铁三角"写作工作坊（在线，¥499-999/期）**

- 4 周，每周一次 2 小时直播
- Week 1：X→Y→Z 自我诊断训练
- Week 2：铁三角——找到你场景里松掉的那一角
- Week 3：识别你自己的死胡同模式（否定螺旋/判断悬置/意象绕圈）
- Week 4：建立你自己的"推进协议"——离开工作坊后怎么自己推自己

**C. 一对一作品诊断（¥1,500-3,000/次）**

- 用户提交 ≤ 10,000 字稿件
- 你人工跑铁三角扫描 + X→Y→Z + 哲学透镜
- 输出：场景审计报告 + 60 分钟视频/语音诊断
- 限量：每月 5 个（人工诊断不能规模化）

#### 平台扩展

| 新增平台 | 用途 |
|---------|------|
| **Bilibili / YouTube** | "诊断你的写作"系列视频——拿匿名投稿做实时 X→Y→Z 诊断 |
| **微信公众号** | 方法论长文 + 工具入口 + 工作坊报名 |
| **Product Hunt** | 诊断工具上线时的英语曝光 |
| **Medium / Substack** | 方法论英语版——"Push, Don't Comfort: A Diagnostic Approach to Writing" |

#### 关键验证指标

- [ ] 工具月活 ≥ 200
- [ ] 付费转化率 ≥ 5%
- [ ] 工作坊满座率 ≥ 80%
- [ ] 一对一诊断复购率 ≥ 30%
- [ ] 月收入覆盖开发/运营成本

### 阶段三（18月+）：规模化 + 平台化

**目标**：月收入 ¥30,000+，产品可脱离你个人运营。

#### 产品升级

**A. 诊断 API（B2B）**

面向做 AI 写作工具的公司，提供诊断层：

```
输入：文本
输出：{
  x_effect: "停滞",
  y_defect: "因果链断裂",
  z_action: "锚定因果",
  iron_triangle: { causal: "loose", character: "tight", tension: "tight" },
  push_resistance: 2,
  persona: "eye"
}
```

定价：按调用量，¥0.01-0.05/call。

这是 v4 表格式架构的直接产物——判定标准表和动作路由表已经完成了 80% 的工程化准备工作。

**B. 白标诊断引擎**

面向写作社区/写作平台（如豆瓣阅读、故事星球、各种写作社群），提供私有化部署的诊断层。

**C. 写作教练认证体系**

将方法论授权给其他写作教练，收取认证费 + 年费。

## 四、平台战术

### 4.1 主攻平台：知乎

**为什么知乎第一优先**：
- 搜索流量长尾——一篇好文章三年后还在获客
- 用户画像精准——大量写作者、文学爱好者、内容创作者
- "诊断"这个框架天然适合知乎的"专业分析"调性
- 竞品薄弱——知乎写作区大量内容是"推荐几本书"，缺乏方法论深度

**内容策略**：

| 系列 | 标题模板 | 频次 |
|------|---------|------|
| X 效果系列 | "你的场景读起来[空洞/模糊/太快]——问题出在[执行缺陷]" | 6 篇，覆盖六个 X |
| 铁三角系列 | "你的场景塌了——可能是[因果/人物/张力]那一角松了" | 3 篇 |
| 死胡同系列 | "你在绕——写作中最常见的三种死胡同" | 3 篇 |
| 认知功能系列 | "你反复写同一个意象——不是风格，是 Ni 聚合陷阱" | 谨慎（铁律8），仅以"写作模式"语言表达 |
| 案例分析 | "这篇 500 字的场景——我跑了铁三角扫描" | 征得同意后匿名发布 |

每篇结尾：引导到自诊问卷或诊断工具。

### 4.2 种草平台：小红书

**为什么小红书**：
- 写作者密度高（#写作 #写小说 #写作干货 标签流量大）
- 视觉化内容天然适合"诊断卡片"
- 女性用户为主——付费意愿强，社群活跃

**内容策略**：
- **诊断卡片图**：把 X 效果判定表做成信息图（6 张，每个 X 一张）
- **铁三角自测清单**：Canva 做图，三列——因果功能 / 人物真实 / 读者张力
- **"5 个问题判断你的场景是否成立"**——互动型内容
- **不露脸视频**：屏幕录制诊断工具的使用过程

### 4.3 深度连接：豆瓣 + 写作社群

**豆瓣写作小组**：
- 直接发"免费诊断"帖——"贴一段你的场景，我告诉你 X 效果是什么"
- 每次诊断都是方法论展示
- 从回复中筛选潜在付费用户（"你这个需要更深的铁三角扫描——私信我"）

**即刻 / Twitter**：
- 每日一条铁律或诊断金句
- 建立"推进者"——不是写作导师，是"那个专门戳破写作幻觉的人"
- 用"推进，不是陪伴"作为 bio

### 4.4 英语市场（阶段二启动）

**Product Hunt + Medium + Hacker News**：
- "Push, Don't Comfort"方法论文章
- X→Y→Z 诊断模型英语版
- 开源诊断工具的基础版本

**为什么英语市场重要**：
- 付费意愿更高
- 方法论稀缺性更强（英语写作书几乎全是"鼓励型"）
- 竞争格局更清晰（Grammarly 做语法，ProWritingAid 做风格，没有人在做"诊断"）

## 五、产品价值拆解

### 5.1 诊断工具的价值三角

```
        精准度
        /    \
       /      \
      /  价值  \
     /   核心   \
    /            \
   /              \
速度 ────────────── 可行动性
```

- **精准度**：X→Y→Z 不是"感觉这段不太好"——是"这段是 X 效果，根源在 Y，你需要做 Z"
- **速度**：即时诊断 vs 等写作小组回复（几天）或编辑反馈（几周）
- **可行动性**：不告诉你"写得不好"——告诉你"锚定因果链。问自己：这个场景改变了什么？"

### 5.2 竞品定位图

```
          诊断精准
              ↑
              │
        ★ /writer
              │
    McKee    │   Truby
    (结构)   │   (人物)
              │
问作者 ──────┼────────── 问文本
"你想表达什么"  │         "文本实际产生了什么效果"
              │
  Grammarly   │  ProWritingAid
  (语法)      │  (风格)
              │
          诊断模糊
```

**/writer 的独特位置**：问文本（不是问作者意图），诊断精准（不是模糊建议）。

### 5.3 为什么现在做

| 趋势 | 机会 |
|------|------|
| AI 写作工具泛滥 | 所有工具都在"帮你写"——没有人在"帮你诊断你为什么写不下去" |
| 写作者 AI 疲劳 | "AI 写的比我快"焦虑 → 需要方法论来区分"人写的东西好在哪" |
| Claude/NotebookLM 等工具普及 | 用户有了 AI 但不善用——他们需要的是诊断框架，不是又一个 AI |
| 写作教育市场空白 | 大量"写作课"教的是"多读多写"——缺乏可操作的诊断方法 |

1. 从 `tables/diagnosis.md` 提取 X 效果判定表（表1），改写为面向写作者的语言（不用术语 X/Y/Z，用"你读自己的文字时感受到什么？"）

**W2 工具 MVP 的技术路径**：

网页（最简单的 HTML 表单）
  → Claude API（system prompt = SKILL.md 压缩版）

  → 输出：X 效果 + Y 缺陷 + Z 推进 + 铁三角松紧

## 七、风险与备选

| 风险 | 概率 | 应对 |
|------|------|------|
| 内容无流量 | 中 | 知乎 SEO 优先——选搜索量高的关键词（"写作卡住了怎么办""场景怎么写"）；前 10 篇不要追求爆款，追求长尾搜索 |
| 诊断工具没人用 | 中低 | 先做"免费诊断帖"验证需求——如果豆瓣免费都没人贴，工具也不用做了 |
| 用户不愿为诊断付费 | 中 | 降低首次付费门槛（¥9.9/月）；或先走"打赏/赞助"模式验证意愿 |
| 被竞品抄袭 | 高（长期） | 方法论是防御——抄得了功能抄不了"推进不是陪伴"的品牌；铁律 + 案例库 + 你的写作实践是护城河 |
| Claude API 成本失控 | 中 | 限免费版字数（500字）；用更便宜的模型做第一层诊断（X 效果判定），贵的模型做深层诊断 |
| 你不想做产品/运营 | 高（需要自我审视） | 如果发现不喜欢——回到路径三（出版加速器/教练服务），放弃路径二（工具）；或者授权方法论给别人做产品 |

## 八、关键原则

1. **先验证，再投入**。在写 10 篇文章之前，先写 1 篇看有没有人读。在开发工具之前，先用人工诊断验证需求。

2. **方法论是产品，你是案例**。不卖"zhong 的写作方法论"——卖"X→Y→Z 诊断体系"。但用你自己的写作过程（三声部、物象系统）作为案例故事来展示方法论的有效性。

3. **推进，不是陪伴——这个核心主张贯穿所有产品**。诊断工具不只是"分析你的文本"——是"推你往前走一步"。工作坊不只是"教写作"——是"帮你找到松掉的那一角然后推你修好它"。

4. **诊断层 > 生成层**。不卖"AI 帮你写"——卖"AI 帮你诊断你为什么写不下去"。"帮你写"是一条红海，"帮你诊断"目前是蓝海。

5. **用工具做流量，用人做利润**。诊断工具是做规模的（月付 ¥29×1000 用户=¥29,000），但一对一诊断和工作坊是做利润和口碑的（¥3,000×5 人=¥15,000）。

## 九、即刻可以做的三件事

不需要等待、不需要开发、不需要审批——

1. **今天**：把 `tables/diagnosis.md` 的 X 效果判定表拿出来，在备忘录里写 500 字——用你自己的话把六种 X 效果讲给另一个写作者听。这不是"写文章"，是"把表翻译成人话"。

2. **明天**：去豆瓣写作小组发一个帖——"免费诊断：贴一段你的场景（≤500字），我告诉你是六种'效果问题'里的哪一种，以及问题出在执行层的哪个位置。"看有没有人贴。有人贴 → 需求存在。没人贴 → 方法论还需要更清晰的价值表达。

3. **本周内**：注册一个知乎专栏 / 小红书账号，把那 500 字发出去。标题用"你的场景读起来'空洞'——不是因为你写得少"。
