# 小白变现第一步：从 Skill 到产品

> 写给完全不懂线上变现的你。每一个步骤都可以照做。

---

## 零、先看清楚你卖的是什么

"X→Y→Z 诊断方法论" 和 "推进，不是陪伴" 是你的核心竞争力，但**用户不会为方法论付钱——用户为"解决我的问题"付钱。**

| 你拥有的 | 翻译成用户的问题 |
|---------|---------------|
| X→Y→Z 诊断 | "我写了一段，感觉不对，但不知道哪里不对" |
| 铁三角监控 | "我的场景读起来没劲，但该写的都写了" |
| 推进策略 | "我知道哪里有问题了，但我不知道怎么改" |
| 推进不是陪伴 | "我不想听'慢慢来'——我想知道下一步具体做什么" |

**你的产品一句话定义：**

> 贴一段文字，告诉你哪里有问题、为什么有问题、下一步具体怎么做。不鼓励，不敷衍，不替你写。

## 一、产品：把 Skill 包装成什么

### 你的 Skill 不能直接卖

你的 `/writer` skill 是 Claude Code 的插件——只有你（安装了 Claude Code + 配置了 skill 的人）能用。别人用不了。

所以你需要把 skill **翻译成一个普通人能用的产品**。

### 产品形态一：网页版诊断工具（推荐起步）

**用户看到什么**：一个网页，一个文本框，一个按钮。
**用户做什么**：贴一段文字（场景/片段），点"诊断"。
**用户得到什么**：一张"诊断报告"。

**诊断报告包含**（直接从 `tables/diagnosis.md` 翻译）：

```
━━━━━━━━━━━━━━━━
📋 你的文本诊断报告
━━━━━━━━━━━━━━━━

🔍 读者感受：[X效果]  
   你的文字让人感觉______。

🧠 问题根源：[Y缺陷]  
   不是写作技巧的问题。是______层面的问题。

🪜 下一步：[Z推进]  
   [一个具体问题，让你自己回答]

📐 铁三角健康度：
   因果功能  ████████░░ 松动——场景改变的东西不够
   人物真实  ██████████ 紧
   读者张力  ██████░░░░ 松动——读者在等但你没给

━━━━━━━━━━━━━━━━
```

**为什么先做这个而不是别的**：
- 开发成本最低（一个网页 + Claude API = 一个晚上）
- 用户理解成本最低（贴文字 → 看报告）
- 可以免费试用 → 收集反馈 → 迭代后再收费
- 直接验证"人们愿意为写作诊断付钱吗"

### 产品形态二：铁三角写作工作坊（第二步）

等你有了第一批用户（哪怕 20 个人说"有用"），再做。

**形式**：4 周在线课程，每周一次直播（腾讯会议/飞书）
**人数**：每期 10-15 人
**价格**：¥399-499/人

**每周内容**：

| 周次 | 主题 | 用户做什么 |
|------|------|----------|
| Week 1 | 学会看 X——读自己的文字像读别人的 | 带一段自己写的场景，用 X 效果判定表自诊 |
| Week 2 | 铁三角——找到你场景松掉的那一角 | 用铁三角判定表检查三个角，标注松的那一角 |
| Week 3 | 你的死胡同——识别你自己的绕圈模式 | 回顾过往卡住的经历，找自己的"死胡同类型" |
| Week 4 | 建立你自己的推进协议 | 写一份"以后卡住了怎么办"的操作手册 |

### 产品不要做什么（起步阶段）

- ❌ 不做 App（开发成本高，获客难）
- ❌ 不做小程序（需要审核，限制多）
- ❌ 不做付费社群（你没有流量基础）
- ❌ 不做 API/SDK（你没有企业客户）
- ❌ 不做英语版（先验证中文市场）

## 二、平台：选一个，做透

你不需要五个平台——你一个都没有精力做。**先做一个，做 20 条内容，然后再看要不要开第二个。**

### 推荐起步平台：小红书

**为什么是小红书而不是知乎**：
- 知乎现在算法极度卷，新人长文很难破零阅读
- 小红书对新人更友好——第一条内容就可能被推送
- 写作/写作干货/写小说 标签下有大量活跃用户
- 图片形式天然适合你的"诊断报告"展示
- 用户付费习惯已经养成（知识付费在小红书很自然）

**发什么**：
- **"诊断报告"截图**：把你跑诊断工具的结果截屏发出来（用户最想看的东西）
- **"六种写作病"图文**：一张图讲一种 X 效果，配一段案例文字
- **"你卡在哪一种"互动贴**：六张诊断卡片，让用户在评论区"打卡"

### 第二平台：豆瓣写作小组

**为什么是豆瓣**：
- 精准——这里的人真的在写作
- 零门槛——发帖不需要粉丝基础
- 你的方法论在这里有"专业感"

**怎么用豆瓣**：
- 不发文章——发"免费诊断"。直接开帖："贴一段你的场景（≤500字），我帮你分析问题在哪里"
- 每次诊断回复都是一次方法论展示
- 从帖子里筛选认真的人，私信邀请试用诊断工具

### 不要做的事

- ❌ 同时做小红书 + 知乎 + B站 + 公众号 + 即刻
- ❌ 花钱投广告（你还不知道谁会买）
- ❌ 找人代运营（你自己的方法论，别人讲不了）

## 三、你的第一步：30 天行动清单

### 第 1-3 天：把诊断跑通

你要先确认一件事：**你的 skill 的诊断能力，能不能在脱离你、脱离 Claude Code 的环境中复现。**

怎么做：

1. 打开 Claude 网页版 (claude.ai)，新建一个对话
2. 把 `SKILL.md` + `tables/diagnosis.md` + `tables/dead-ends.md` + `tables/thresholds.md` + `iron-laws.md` 的内容粘贴到 system prompt（或直接粘贴在第一条消息里，说"请按以下规则行事"）
3. 贴一段你自己的文字进去
4. 看它输出了什么
5. 如果输出质量不够好——调整 prompt，直到诊断结果你觉得"可以给另一个人看"

> 这会告诉你：你的方法论能否脱离你本人运行。这是产品化的第一步——能脱离你，才能变成产品。

### 第 4-7 天：做诊断工具 MVP

不需要你会写代码。用下面这条路：

**方案 A：如果你愿意学一点 Cursor/Lovable（推荐）**

1. 打开 [lovable.dev](https://lovable.dev) 或 Cursor
2. 描述你要的东西："一个网页，有一个大文本框，用户粘贴文字后点'诊断'按钮，调用 Claude API 进行文本诊断，展示诊断报告"
3. AI 会帮你生成一个网页
4. 部署到 Vercel/Netlify（都免费，一键部署）

**方案 B：零代码起步（更快，但丑一点）**

1. 用 Google Form 做一个"写作诊断申请"
2. 用户填写：名字、邮箱、文本内容
3. 你手动跑 Claude，把诊断结果邮件回复
4. 每天限 10 份免费

方案 B 看起来蠢，但可以立刻开始——**不需要开发，不需要域名，不需要部署。**它验证的是：有没有人愿意花时间"申请诊断"。

### 第 8-14 天：免费跑通 20 次诊断

目标：在两周内，为 20 个不同的人做免费诊断。

怎么找这 20 个人：

1. 豆瓣写作小组发帖（"免费帮看 10 段场景"）
2. 小红书发帖（"你的小说卡在哪里？免费文字诊断"）
3. 发给认识的在写作的朋友
4. 在你的写作社群/读者群/校友群里发

**每做完一次诊断，问对方三个问题**：
1. "诊断结果对你的实际写作有帮助吗？如果只能留一句，留哪句？"
2. "这个诊断值得你付多少钱？（不是让你付——我想知道价格感知）"
3. "你最希望这个诊断工具还能做什么？"

把 20 个人的回答整理出来——这就是你的产品方向和定价依据。

### 第 15-21 天：整理案例 + 第一次公开发布

把前面做过的诊断（征得对方同意，匿名处理）整理成"诊断案例"：

```
案例：一个"停滞"的场景

原文：[匿名处理的场景片段]
诊断：
  X = 停滞——连续三句写同一位置的物件，因果链没有推进
  Y = 锚点缺失——场景有动作但没有情感核心
  Z = "这个场景的情感核心是什么？不要用形容词——用动词。"

用户反馈："我第一次意识到我一直在'看'同一个东西而不是'用'它。"
```

在小红书/知乎发这篇案例。这是你第一件真正有传播力的内容。

### 第 22-30 天：第一次收费

到了这一步，你有：
- 20 次诊断经验
- 若干匿名案例
- 一个能用的（哪怕是手动）诊断流程
- 至少几个说过"这个应该收费"的用户

**第一次收费怎么做**：

最简单的收费产品：**"深度诊断报告"**

- 用户提交 ≤ 3000 字文本
- 你手动跑 Claude + 人工覆审
- 输出：X→Y→Z 诊断 + 铁三角扫描 + 场景审计（即 `tables/diagnosis.md` 的场景审计模板）
- 价格：**¥9.9/次**

为什么是 ¥9.9：
- 足够便宜到"试一下不心疼"
- 但又需要付款——验证真实的付费意愿
- 如果 20 个免费用户里 3 个愿意付 ¥9.9 → 你有转化率数据了
- 然后慢慢涨价：¥9.9 → ¥19.9 → ¥29/月 订阅

**收钱工具**：爱发电 / Afdian（最简单的创作者收费平台，不需要营业执照）

## 四、核心问题：你一个人用 vs. 给别人用的差异

这是最关键的部分。你的 skill 在你手里好用，不意味着直接给别人也好用。

### 差异一：上下文差异

| 你使用 | 别人使用 |
|--------|---------|
| Claude 加载了全部 21 个文件（1001 行） | 产品只能加载核心表（约 200 行 prompt） |
| AI 知道你的写作历史、私人概念、三声部画像 | AI 第一次见到这个用户 |
| 你理解 X/Y/Z 术语，不需要解释 | 用户不理解，需要在报告里解释每个术语 |

**解决方案**：
- 产品 prompt 只加载核心表（diagnosis + dead-ends + thresholds + iron-laws）
- 诊断报告的措辞必须"去术语化"——写"读者感受"不写"X 效果"
- 个性画像功能留到 v2——第一版不做个性化

### 差异二：对话 vs. 单次诊断

| 你使用 | 别人使用 |
|--------|---------|
| 你和 Claude 多轮对话——推了再推 | 用户只贴一次文字，拿到一次报告 |
| 你可以说"不对，不是这个"，AI 回滚 | 用户拿到报告后不知道怎么回应 |
| AI 可以根据你的反应调整策略 | AI 没有反馈信号 |

**解决方案**：
- 诊断报告末尾加一个"追问"入口——"这个诊断对你有用吗？如果有，下一段你想看什么？"
- 报告不要只给一个答案——给 2 个可选方向，让用户选
- 订阅版才能做多轮对话（月付的价值就在这里——不是无限诊断，是"跟着你的作品走"）

### 差异三：你的写作水平 vs. 用户的写作水平

| 你使用 | 别人使用 |
|--------|---------|
| 你的写作是严肃的文学实践 | 用户可能是网文写手 / 同人写手 / 刚起步的写作者 |
| 你的私人概念体系（悬置/异化/how for）对你有意义 | 对别人可能是障碍 |
| 你读得懂深层诊断 | 别人可能觉得"铁三角"莫名其妙 |

**解决方案**：
- 产品从最简单版本开始——先只提供 X→Y→Z 三段，不出铁三角、CF 诊断、哲学透镜
- 等用户说"我还想看更深的"再追加深度诊断层
- 或者做分级：基础版只出 X→Y→Z（¥9.9），进阶版加铁三角（¥29.9），专业版加强深层诊断（¥99）

### 差异四：推阻计数器的问题

你的 skill 有一个核心机制：**推阻计数器**——用户绕一次 +1，到 4-5 触发制高点，到 6+ 最后防线。

这个机制在**单次诊断产品中完全用不了**——因为没有"对话回合"来累积。

**解决方案**：
- 单次诊断不做推阻计数
- 订阅版（多轮对话）才做——这就是为什么"多轮对话"是你的付费核心价值
- 单次诊断可以加一句"如果你拿到了诊断但还是卡住了——那是正常的。每个人的第一轮诊断可能没命中。"（这是人的话，不是推阻计数器）

### 差异五：质量控制的差异

| 你使用 | 别人使用 |
|--------|---------|
| 你能判断 AI 诊断对不对——可以对 AI 说"不对" | 用户不具备诊断能力，AI 说错了他也不知道 |
| 你有一套回滚机制 | 用户只能接受或放弃 |

**这是产品最大的风险**：AI 的诊断可能不准，而用户不知道。

**解决方案**：
1. **诊断报告加免责说明**："这个诊断是 AI 基于文本模式的分析，不是绝对判断。如果你的直觉说'不是这个'——相信你的直觉。"
2. **加"不准"按钮**：如果用户觉得不准，可以点"这个诊断不准"——积累数据，持续优化 prompt
3. **人工抽检**：每天抽检 5-10 份 AI 诊断报告，看质量是否下滑
4. **诊断置信度标注**：把诊断分成"高置信度"和"仅供参考"两级——X→Y→Z 是高置信度的，CF 深层诊断是仅供参考的

## 五、具体价格与产品阶梯

当你从小红书/豆瓣吸引到人，你需要一个清晰的产品阶梯让他们"走上去"：

```
免费层：小红书/豆瓣公开诊断帖
  ↓ 想"再多看一段"
¥9.9/次：单次深度诊断（一段文字，X→Y→Z 报告）
  ↓ 想"跟着我的作品走"
¥29/月：月度订阅（不限次数 + 多轮对话 + 铁三角扫描）
  ↓ 想"我需要一个人看我的完整手稿"
¥499/次：完整手稿诊断（≤ 5 万字，人工覆审 + 1 小时视频通话）
  ↓ 想"我不要产品，我要方法论"
¥899/人：铁三角写作工作坊（4 周，10-15 人）
```

**关键原则**：每一层的价格是上一层的 3-5 倍。用户永远有一个"更便宜"和"更贵"的选择——但"更便宜"就够了，"更贵"让他知道你还有更深的东西。

## 六、三个不可避免的问题

### 问题一：没人来怎么办

如果你的前 5 篇内容都没人看、前 10 个诊断没人申——

**诊断自己的问题**：
- 标题有没有说清楚"你能得到什么"？（不好的标题："写作诊断服务" → 好的标题："贴一段你的小说，我告诉你哪里让读者想关掉"）
- 你有没有在诊断回复中展示方法论的价值？（不只是说"这里有问题"，而是让对方觉得"原来是这样"）
- 你有没有让每个拿到免费诊断的人帮你传播？（"如果觉得有用，帮我推荐给一个也在写作的朋友"）

如果调整后还是没人——换平台。从小红书换到知乎，或从线上换到线下（参加线下写作活动，现场给人做诊断）。

### 问题二：AI 诊断真的有用吗

这是你的产品最根本的风险。你需要自己能诚实回答这个问题。

**验证方法**：你自己用产品版 prompt（不是完整 skill）跑 20 次诊断，对比完整版 skill 的诊断结果。如果产品版只有完整版 60% 的诊断质量——不是产品的问题，是 prompt 需要优化。如果产品版和完整版差不多——那就没问题。

### 问题三：你厌烦了怎么办

如果你做了一周，发现"我不想运营小红书/回复诊断/卖东西"——这是完全正常的。

这时候需要问自己一个问题：**我是想做写作教练，还是想做产品？**

- **写作教练**：放弃产品开发。就做一对一诊断 + 工作坊。每次收 ¥500-3000。一个月做 5-10 个客户。不需要平台、不需要运营、不需要写代码。只需要口碑。
- **产品**：放弃"每个用户都是我亲自诊断"。把诊断自动化。忍受前期的低质量和高成本。规模化。

**两个都想要 → 两个都做不好。**起步阶段选一个。

## 七、你现在就该做的事

打开手机备忘录，写下面这段话——这就是你的产品介绍：

> 我是一个写作者。我做了一个写作诊断工具。
> 
> 你贴一段文字——小说的一段场景、文章的一个段落——它会告诉你：
> 1. 这段文字让读者感受到什么（空洞？模糊？太快？停滞？）
> 2. 问题出在执行层的哪个位置（不是写作技巧——是你写之前就没想清楚的东西）
> 3. 下一步具体做什么（不是一个模糊的建议——是一个你回答之后就知道怎么改的问题）
> 
> 我不会鼓励你。不会说"慢慢来"。不会替你写。
> 
> 推进，不是陪伴。
