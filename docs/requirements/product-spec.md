## 1. 产品概述

### 1.1 产品定位
一款基于 **X→Y→Z 诊断模型**的镜像式写作推进工具。不评判、不陪伴、不写好话——推进是唯一目标。工具反射文字，让写作者看见自己的思考模式。

### 1.2 目标用户
- 正在写作任何类型文字的人（小说、随笔、论文、日记）
- 卡在某一段文字中、不知道"下一步往哪走"的写作者
- 需要一面"镜子"而非一个"导师"的创作者

### 1.3 核心价值
- **推进，不是陪伴**：每次交互输出一个可执行的动作指令
- **透明化诊断**：用户看到判断的依据，而非仅看到结论
- **镜像式协助**：工具反射文字，不替代写作者

---

## 2. 核心方法论

### X→Y→Z 诊断模型

| 阶段 | 说明 | 边界 |
|------|------|------|
| X（读者效果） | 文字让读者感受到了什么——空洞？模糊？停滞？散焦？ | 工具判断 |
| Y（执行缺口） | 执行层面缺了什么——因果链断裂？锚点缺失？人物退场？ | 工具判断 |
| Z（推进方向） | 约束问题 + 动作指令——用户回答完就知道下一步做什么 | 工具提问，用户执行 |

### 三维度观察
- **因果推进**：读者知道"所以呢？"还是不知道？
- **人物驱力**：行动来自内心还是来自情节？读者信不信？
- **读者注意**：读者在等什么？还是没东西可等？

## 3. MVP 功能范围

### v1.0 必须实现
| 功能 | 说明 | 优先级 |
|------|------|--------|
| 文字输入 | 文本框，支持粘贴任意长度文字 | P0 |
| 诊断输出 | 按输出格式渲染诊断报告 | P0 |
| 透明链路 | 显示"我注意到"段——诊断的文本依据 | P0 |
| 三个维度观察 | 因果推进/人物驱力/读者注意 | P0 |
| X→Y→Z 路由 | 后端按路由表执行诊断逻辑 | P0 |
| 追问机制 | 用户点"不对"时换角度重新诊断 | P1 |
| 进步指认 | 用户贴修改后文字时识别具体改善 | P1 |
| 长文本处理 | >500字自动截取最需诊断的段落 | P1 |
| 三角全紧识别 | 三个维度都在工作时跳过诊断 | P1 |

### v1.0 不做
- 用户账户系统
- 写作历史存档
- 多段连续诊断会话
- 导出/分享功能
- 付费墙

### 后续版本
- 写作模式识别（用户的重复性认知习惯）
- 多段连续诊断（诊断→修改→再诊断→再修改的链条）
- 写作日历（追踪写作频率和进步轨迹）
- 社区/分享功能

## 4. 用户流程

```
用户打开页面
    ↓
粘贴文字（≥20字）
    ↓
点击"开始诊断"
    ↓
系统执行 X→Y→Z 诊断
    ↓
渲染诊断报告（含"我注意到"+ 三维度观察）
    ↓
用户判断：
  ├── "有用" → 按动作指令继续写 → 粘贴新的/修改后的文字
  │      ↓
  │   系统识别修改 → 若有改善给出具体指认
  │
  ├── "不对" → 系统换 Y 重新诊断 → 输出新报告
  │
  └── 三角全紧 → 系统说"继续写下一段"
```

## 5. 设计约束

### 铁律（不可偏离）
1. 推进是第一目的
2. 每句话说完用户必须能接
3. 不评价好坏
4. 不替用户写（动作指令是方向不是示范）
5. 不给台阶（不说"慢慢来"、"已经很不错了"）
6. 判断要确定（不说"或许"、"可能"）
7. 不问空问题
8. 不用术语
9. 只诊断当前文字

### 品牌语调
- 直接、不啰嗦
- 不说废话、不说套话
- 不卖萌、不装亲和
- 像一面镜子——客观、清晰、不评价

## 6. 测试标准

在 claude.ai 测试通过以下全部 checklist 后，方可进入网页开发阶段：

- [ ] X→Y 匹配正确
- [ ] 输出以"我注意到"开头
- [ ] 三维度是纯观察句——无进度条和紧/松标签
- [ ] Z 包含动作指令
- [ ] 动作指令是方向不是示范
- [ ] 追问流程正确
- [ ] 无评价词汇
- [ ] 三角全紧时跳过诊断
- [ ] 修改后文字有具体进步指认
- [ ] 长文字能正确截取
- [ ] 输出格式每次一致
- [ ] 无内部术语泄漏
