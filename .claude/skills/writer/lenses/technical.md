# 信息透镜 — 技术/学术文本分析

> 适用于：技术文档、学术论文、产品规格、教程、API 文档、知识库条目、technical writing、academic prose、documentation。
> 不适用于：技术博客中的观点部分（→逻辑透镜）、教程中的叙事举例（→可能需叙事透镜辅助）。

## 体裁识别确认

加载本透镜后，先确认体裁假设：
- 文本的目的是否为"传递信息/知识"而非"说服"或"讲述"？→ 确认
- 是否包含定义、分类、步骤、规格等结构化信息元素？→ 确认
- 信息是否有明确的层级（大概念→小概念→细节）？→ 确认
- 若三项中 ≤1 项成立 → 降级为通用透镜

## 本体裁 X→Y→Z 映射表

| 层 | 技术/学术文本的问题 | 诊断维度 |
|----|-------------|---------|
| **X — 表面效果** | 读者读到了什么信息？信息以什么顺序出现？读者在哪个位置需要停下来重新读？ | 信息清晰度 / 信息密度 / 可追踪性 |
| **Y — 结构动力学** | 信息的组织方式是否帮助读者理解？定义是否在使用前给出？步骤之间的顺序是否合理？术语是否一致？ | 信息架构 / 定义精度 / 术语一致性 / 步骤完整度 |
| **Z — 揭示与方向** | 哪个位置的信息架构让读者可能走偏？哪个定义是模糊的？哪个步骤缺了前置条件？ | 指向一个信息缺口或架构问题 |

### 技术文本质量三角

| 角 | 松动信号 | 诊断问题 |
|----|---------|---------|
| **定义精度** | 关键术语未定义，或定义在使用之后才出现 | "读者第一次遇到这个词的时候——他知道它的意思吗？还是他需要往回翻？" |
| **信息架构** | 信息层级不清晰——并列的应该是父子，或顺序应该是因果 | "这三个点——它们是并列的还是一个包含另外两个？读者读完这三段后能画出层级图吗？" |
| **步骤完整** | 操作步骤缺前置条件或后置状态 | "从 A 到 B——中间的操作读者能执行吗？还是他需要额外假设一些条件？" |

三角全紧 → 信息架构成立。不碰结构，指出可扩展的方向。

## 分析协议

### 第一步：信息架构提取
- 核心信息是什么？（能用一句话概括吗？）
- 信息以什么结构组织？（层级树？线序步骤？矩阵对比？网状关联？）
- 读者沿什么路径消费信息？（从上到下？跳转？搜索式？）

### 第二步：信息质量扫描
- 术语：第一次出现时是否定义？术语是否前后一致？（同一个东西有没有换名字？）
- 步骤：每一步的前置条件和后置状态是否明确？步骤之间有无遗漏？
- 粒度：有没有地方信息密度突变——一段极详细，下一段极概括？
- 读者负担：哪个位置读者需要额外知识才能理解？那个知识有没有被给出？

### 第三步：缺口定位
- 对读者最关键的缺失信息是什么？
- 哪个地方的信息组织形式和内容不匹配？（比如应该用列表但用了段落，应该用时序但用了层级）

## 禁止项

| 禁止 | 原因 |
|-----|------|
| 替你补充缺失的技术信息 | 镜子不知道你的技术细节——只能指出"这里缺了"，不能说"这里应该写 X" |
| 用风格偏好替代信息诊断 | "段落太长"不是诊断——"三段信息没有层级标记，读者需要自己排序"才是 |
| 假装理解不理解的术语 | 遇到未知术语——标注"此术语未定义"而不是猜它的意思 |

## 输出调整

- 【特征】：可选。指出信息架构类型（树形/线序/矩阵/网状）、术语密度、读者前置知识假设
- 学术文本：注意引用密度、论证与信息陈述的比例、学科惯例
- 技术文档：注意操作动词的精确度（"点击"vs"选择"vs"进入"——每个词是否准确对应一个动作）
- 英文技术文本分析维度（内部参考·输出时用目标语言描述现象）：被动语态在步骤描述中是否隐藏了操作主体

## 深度分析触发

- 结构专制（信息架构绑架内容，内容为结构服务而非反过来）→ `reference/cognitive-functions.md`（Te 结构专制）
- 术语闭环（自创术语体系未与外部标准对接）→ 标注但不切换透镜
- 信息密度突变模式 → 可选升级至通用透镜以获取更广泛的分析

## 焦距优先级与动作句方向库

> 动作句 = 颜色手势（[G-5 §3](../../../docs/tech/action-sentence-templates.md#3-六色信号--六种动作句型)）+ 焦距证据（[G-5 §4](../../../docs/tech/action-sentence-templates.md#4-焦距--动作词汇映射)）+ 体裁方向（本节）。铁律 #9（推≠替写）、#10（动作句优先）约束所有动作句。

**焦距优先级**：语言 ★★★ / 结构 ★★★ / 语义 ★★ / 语用 ★★ / 情感 ★ / 批判 ★

### 技术方向库

| 方向 | 动作句尾句 |
|------|----------|
| 术语定义前置 | "读者第一次遇到这个词的时候——他知道它的意思吗？" |
| 信息层级清晰化 | "这三个点——是并列的还是层级关系？" |
| 步骤完整性 | "从A到B——中间缺了什么前置条件？" |
| 操作动词精确 | "每一个动词——对应一个具体的手的动作吗？" |
| 读者负担评估 | "读者在这个位置需要什么知识——你给了吗？" |

### 语言层动作句（★★★ 核心焦距）

```
术语未定义（胭脂红）：
"这里停下来——'{W}'在{P}第一次出现，但读者还不知道它的意思。
 定义在{N}段之后才来——读者需要往回翻。
 如果读者不往回翻——他能靠上下文猜出来吗？"

操作动词不精确（胭脂红）：
"'{W1}'、'{W2}'、'{W3}'——这三个动词在描述用户操作。
 它们精确对应了三个不同的动作吗？还是同一个动作用了三个名字？
 读者需要知道——'{W1}'和'{W2}'之间，手在做什么？"
```

### 结构层动作句（★★★ 核心焦距）

```
层级错位（胭脂红）：
"这里停下来——这三个点在{P}被并列列出。
 但它们不是并列的——{W1}包含{W2}和{W3}。
 读者读完后画出的层级图——和你想的一样吗？"

步骤缺前置（钢蓝）：
"注意——从'{W1}'到'{W2}'，中间的操作——读者能执行吗？
 前置条件是什么？后置状态是什么？
 如果读者不知道——他会在这一步卡住。"
```

### 推荐焦距简化模板

```
语义层·术语一致性：
"'{W1}'在{P1}，'{W2}'在{P2}——它们在说同一个东西吗？
 同一个概念换了名字——读者会以为这是两个不同的东西。"

语用层·读者预设：
"文本在{P}预设读者知道'{W}'。
 如果读者不知道——他还有入口吗？还是从此被关在门外？"
```
